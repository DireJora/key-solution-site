# n8n: автоматизации «Ключевого решения»

В каталоге `workflows/` находятся выключенные экспорты workflow:

- `site-lead-amocrm-telegram.json` — производственный маршрут: заявка с сайта → проверка дублей → контакт и сделка в amoCRM → примечание → уведомление в Telegram;
- `sla-escalation-telegram.json` — каждые 30 минут проверяет просроченные задачи `KS-SLA`, убеждается, что сделка всё ещё находится в статусе «Новая заявка», и один раз уведомляет общую Telegram-группу;
- `normative-search.json` — поиск по allowlist официальных доменов ЕЭК, ФСБ, ФТС, Росаккредитации и другим государственным источникам;
- `normative-extract.json` — извлечение текста только из заранее выбранных официальных URL.

## Заявки сайта

На сервере производственный workflow активен под ID `keySolutionDeliveryTelegramDraft20261107`. Экспорт в репозитории специально сохранён с `active: false`, чтобы импорт не включил внешние записи автоматически.

Workflow SLA-эскалации активен под ID `keySolutionSlaEscalation20261109`. От повторной отправки защищает маркер `KS-SLA-ALERT:<task_id>` в примечании сделки amoCRM. Его экспорт также сохранён с `active: false`.

Workflow использует два зашифрованных подключения n8n, значения которых в экспорт не входят:

- `amoCRM — Ключевое решение` (`HTTP Bearer Auth`);
- `Cloudflare Telegram Relay — Bearer` (`HTTP Header Auth`).

Рабочий webhook: `key-solution-crm-delivery-telegram-v2`. Backend передаёт заявку только после локальной записи в JSONL. Повторный UUID не должен создавать новую сделку, контакт, примечание, SLA-задачу или Telegram-уведомление.

Для каждой новой заявки workflow создаёт в amoCRM задачу типа «Звонок» на ответственного по сделке со сроком через один час. Перед созданием выполняется проверка существующей незавершённой задачи с тем же маркером `KS-SLA`, чтобы повторная доставка не создала дубль.

Перед включением после импорта нужно проверить credential, ID воронки и статуса amoCRM, chat ID Telegram, URL relay и выполнить синтетический тест в воронке `TEST`.

## Проверенное состояние

- поиск через Firecrawl вернул пять официальных источников;
- извлечены страница ФСБ и PDF ЕЭК;
- источник ФТС вернул ошибку внутреннего прокси Firecrawl, которая сохраняется вместе с URL;
- результат явно помечается как материал для проверки человеком, а не готовое юридическое заключение;
- workflow не активированы, не имеют расписания и не меняют amoCRM.

## Импорт

Workflow ссылаются на credentials n8n. Экспорт не содержит API-ключи, Bearer-токены или Telegram Bot Token. После импорта подключения нужно создать или выбрать внутри n8n; секреты нельзя добавлять в JSON, `.env` репозитория или GitHub Secrets без отдельной необходимости.

До подключения Telegram, amoCRM или публичного webhook нужно добавить проверку входных данных, allowlist доменов и подтверждение Кириллом перед любым юридическим выводом или внешним сообщением.
